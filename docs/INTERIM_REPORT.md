Все данные синтетические. Всё, что названо «проверено», подтверждено тестом, оценкой или логом. Файл заменяет прежние промежуточные версии.

## 1. Что получилось

Радар мулов между банками плюс копилот аналитика. Каждый банк считает свой риск локально. Между банками ходят только зашифрованные сообщения протокола PSI (выходные счета кандидатов). Радар раскрывает кластер, только если он охватывает ≥ 2 банка и ≥ 3 кандидата; банк получает: «ещё N кандидатов в M других банках, вот совпавшие счета». Человек решает; модель объясняет и пишет черновик, но не решает.

```
банк B1/B2/B3: признаки -> правила A/B/C -> детекторы D1..D8 -> слой невиновности E1..E8 -> кейс (score, приоритет, triage)
        |  кандидаты -> токены счетов -> DH-PSI (попарно)  ->  радар: кластеры
        |  <- cluster_id, число других банков/кандидатов, совпавшие счета, грубая статистика
copilot (Bedrock Kimi-K3 / Sonnet 4.5): объяснение CS/EN, раздел V OPO, вопросы к правилам, 4 агента (только чтение + предложения)
аудит (SHA-256 цепочка) · API (FastAPI) · интерфейс (React, 8 экранов) · отдельные процессы банков (distributed mode)
```

## 6. Что не работает или не доказано

- **Сильный тезис «PSI находит то, что один банк не видит» не доказан.** Подтверждена слабая форма: радар поднимает слабые сигналы и в среднем чуть улучшает метрики; мулов без локального сигнала не находит. Два held-out мира — малая выборка.
- **Метрики на подложенных сценариях измеряют узнавание наших же определений схем**, не реальную полноту. Разделители E6–E8 придуманы нами против наших же персон.
- **IBM:** движок слабый, радар полезен только в ранжировании.
- **Сети мулов в данных ČNB отсутствуют**, правило A — шум (60–99.9 % клиентов).
- **Черновики OPO у мулов часто идут с замечаниями QA:** модель за 3 попытки не всегда укладывается в проверку ссылок и чисел. Замечания показаны человеку в самом документе, черновик не выдаётся за готовый.
- **API/UI используют внутрипроцессный радар;** распределённый режим работает отдельно (`scripts/run_local_cluster.py`) и в API/UI не подключён. Агенты работают в процессе API.
- **Нет:** TLS и аутентификации между сервисами, хранилища ключей, запуска `docker compose`, Clean Rooms / Nitro Enclaves / AgentCore, клиентских текстов, анализа повторных запросов между сессиями, mypy вне ядра.
- **Заглушки:** курсы FX, матрица эскалации, реквизиты банка, цены моделей; список ЕС не сверен.
- **Удаление последней записи цепочки аудита не обнаруживается** без внешнего якоря (в документе отмечено).
