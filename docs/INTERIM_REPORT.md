# Stáj — актуальное состояние проекта

Дата: 19.10.2026, вечер. Все данные синтетические. Документ заменяет первый промежуточный отчёт. Всё, что здесь названо «проверено», подтверждено тестом, оценкой или логом; остальное прямо помечено.

## 1. Что строим и как это устроено

Радар мулов между банками плюс копилот аналитика. Каждый банк считает свой риск локально. Между банками ходят только зашифрованные сообщения протокола PSI (общие выходные счета кандидатов). Если совпадений достаточно, радар раскрывает кластер, и банк видит: «ещё N кандидатов в M других банках, вот общие счета». Человек решает. Модель объясняет и пишет черновик, но не решает.

```
банк B1/B2/B3: признаки -> правила A/B/C -> детекторы D1..D8 -> слой невиновности -> кейс (score, приоритет, triage)
        |  кандидаты -> токены счетов -> DH-PSI (попарно)  ->  радар: кластеры (>=2 банка, >=3 кандидата)
        |  <- cluster_id, число других банков/кандидатов, совпавшие токены, грубая статистика lag/retention
copilot (Bedrock): объяснение CS/EN, раздел V OPO, 4 агента с инструментами "только чтение + предложения"
аудит (хеш-цепочка) · API (FastAPI) · интерфейс (React)
```

## 2. Как делается работа (способы)

| Способ | Что делает | Где |

| Агент Opus (интерфейс) | 7 экранов React/Vite/Tailwind/Cytoscape/Recharts на моках; потом подключён к реальному API | `ui/` |

Аудитор радара (до последних правок) проверил пять миров: радар добавляет +0…+3 найденных мула при пороге 30 и +3…+7 при пороге 40, без лишних ложных срабатываний. Мулы без всякого локального сигнала остаются пропущенными (7 из 15 скрытых на сиде 101). **Вывод: сильный тезис «PSI находит то, что один банк не видит» не подтверждён; слабая форма «радар подтверждает и поднимает слабые подозрения» подтверждена.**

После замечаний аудитора исправлено: двойной учёт кластера в приоритете, нулевая гипотеза D6 (теперь по всем клиентам банка). До исправления локальный D6 не срабатывал на сиде 101 по невезению. На остальных сидах итог ещё не пересчитан.

Честные персоны: 0 из 54 помечены на сиде 101 при пороге 30 (при любом приоритете часть помечалась бы). Без слоя невиновности ложные срабатывания растут с 7 до 22. Без D6/D7 recall падает до 0.64.

**ČNB (5 493 клиента, 397 853 транзакции; сетей мулов нет).** Правило A: 3 313–5 489 клиентов в зависимости от единиц; B: 4 алерта (все PEP); C: 16 алертов (14 закрыты как FP, 2 в REVIEW). Всего 4 670 кейсов: 4 659 закрыто автоматически, 11 в REVIEW, из них 8 с приоритетом ≥ 30. «Мама»-персона (232 клиента с ≥ 2 переводами одному получателю): 2 попали в REVIEW (0.86 %).

**Bedrock.** Проверка трёх моделей: 48.8 с, все прошли tool-use. Kimi-K3: объяснение 177 с (2 попытки), раздел V 209 с (3 попытки), 0 нарушений QA. Sonnet 4.5: 40 с и 52 с, 0 нарушений. Агенты на Kimi: triage 117 с (7 вызовов инструментов), investigation 154 с (12), narrative 146 с (4). Найдено и исправлено на живых прогонах: формат `toolResult` (только объект), `temperature` у Kimi, таймаут чтения, смысловая ошибка модели (доля прочитана как срок), несуществующий id сигнала в тексте агента (теперь флагуется).

**Тесты:** 116 собираются; последний полный прогон до правок агентов — 102 passed; PSI-property и e2e радара после ускорения — 7 passed.

## 6. Что не работает или не проверено

- **Сильный тезис радара не доказан** (см. выше). Подавать как «поднимает слабые сигналы при минимальном раскрытии».
- **Нет независимого held-out:** сиды 202, 303, 404 аудитор уже видел, поэтому они считаются dev; для итога заведены сиды 505 и 606, итоговый прогон ещё не делался.
- **PSI медленнее цели** (см. п. 22 выше).
- **Правило A — шум** (60–99.9 % клиентов); ценность в слое триажа.
- **Нулевые ложные срабатывания на честных персонах** держатся на пороге 30 и на разделителях, придуманных после того, как мы увидели ложные срабатывания на своих же персонах. Это не независимое доказательство.
- **`naive_raw_sharing` не гарантированная «верхняя граница»:** данные сливаются в один узел с порогами, настроенными на банк.
- **Не проверено глазами на реальных данных:** экраны Radar, Metrics, Audit, OPO, Honesty (очередь работает).
- **POST-ручки API** (решение с конфликтом интересов, четыре глаза, правка раздела V) без автоматических тестов.
- **Не сделано:** вопросы к правилам в copilot, PDF для OPO, выгрузка CSV для ČNB и пакета OPO по лучшим кейсам, mypy, hypothesis-тест цепочки аудита, README, `pitch_numbers.json`, `eval/report.md/json`.
- **Список ЕС по высокому риску не сверен**; курсы FX, матрица эскалации, реквизиты банка, цены моделей — заглушки.
- **Три банка пока в одном процессе** (разделение данных есть, разделения процессов нет) до результата агента распределённого режима.
- **Не используются:** AWS Clean Rooms, Nitro Enclaves, Bedrock AgentCore.
